# Release

## Prerequisites

- Windows 10/11 x64
- Node.js 22.15+
- An unpacked Electron distribution (44.x recommended; DSH Hub is tested with
  Electron 44.7.0 / Chromium 152 / Node 24.21)
- Optional: Windows .NET Framework `csc.exe` (included with Windows 10/11) for
  the tiny icon/version launcher. Without it the build falls back to using the
  Electron runtime as the main EXE.
- A readable DSH Home with at least one profile, so the build can run and embed
  the packaged self-test. Set `DSH_HUB_SKIP_SELF_TEST=1` only when intentionally
  packaging without DSH data.

## Build

```bash
npm install
npm run package:win
```

If Electron's binary was not downloaded automatically:

```bash
# download/install once, or point at any unpacked Electron dist
ELECTRON_DIST="D:/path/to/electron/dist" \
DSH_HUB_RELEASE_DIR="<delivery>/release" \
npm run package:zip
```

The output is a portable folder:

```
release/
└─ DSH-Hub-0.2.2-win-x64/
   ├─ DSH-Hub.exe             (small .NET launcher with icon/version)
   ├─ DSH-Hub-Runtime.exe     (Electron runtime)
   ├─ <Electron runtime files>
   ├─ resources/app/          (application source)
   ├─ data/
   │  ├─ self-test.json       (generated by the build self-test)
   │  ├─ logs/                (empty until first run)
   │  └─ crashes/             (empty until first crash)
   └─ 启动说明.txt
```

`--zip` additionally creates `DSH-Hub-0.2.2-win-x64.zip` with the Windows
system `tar.exe` (fallback: PowerShell `Compress-Archive`).

## Installer

A single-EXE installer can be built from a portable release with Inno Setup 6:

```powershell
winget install --id JRSoftware.InnoSetup -e
$env:DSH_HUB_APP_DIR = "<delivery>\release\DSH-Hub-0.2.2-win-x64"
$env:DSH_HUB_INSTALLER_OUT = "<delivery>"
$env:DSH_HUB_INSTALLER_STAGE = "<delivery>\installer\payload"
npm run installer:win
```

This produces `DSH-Hub-<version>-Setup.exe` and
`DSH-Hub-<version>-Setup.json`. The script copies and sanitizes the payload
(only `data/self-test.json` is retained; live logs/settings/Chromium caches are
never shipped), then compiles `installer/DSH-Hub.iss`.

Installer properties:

- per-user install, `PrivilegesRequired=lowest`
- default `%LOCALAPPDATA%\Programs\DSH Hub`
- **custom install directory page enabled** with a writability check
- Start Menu shortcut, optional desktop shortcut, uninstaller
- Chinese Simplified UI
- the installed app receives the same self-test evidence

The installer build requires the source portable release to contain a valid
`data/self-test.json`. See `installer/README.md` for detailed staging and
silent-install test commands.

## What the script does

1. Copies the Electron dist, excluding its default app.
2. Renames `electron.exe` to `DSH-Hub-Runtime.exe`.
3. Compiles `scripts/launcher-dsh-hub.cs` into a small WinExe `DSH-Hub.exe`
   with the app icon and version resources (falls back to renaming the runtime
   when `.NET Framework csc.exe` is unavailable).
4. Copies `src/`, `assets/`, `docs/`, README, LICENSE and notices into
   `resources/app/`.
5. Writes a minimal runtime `package.json`.
6. Creates portable `data/logs` and `data/crashes`.
7. Runs the built `DSH-Hub.exe --self-test` in the output folder, verifies
   `ok === true`, prunes Chromium caches/transient markers, and **keeps
   `data/self-test.json` in the package**.
8. Optionally zips the folder.

## Self-test evidence

The build fails if the packaged self-test does not pass or does not create
`data/self-test.json`. The JSON includes `isPackaged`, Electron/Node versions,
profiles, plugin/session/skill counts and model credential status (masked). It is
read-only with respect to the DSH profile.

To re-run in the release folder:

```bash
./release/DSH-Hub-0.2.2-win-x64/DSH-Hub.exe --self-test
```

It overwrites `data/self-test.json` and exits with code 0 on success. To build
without DSH data (for example in CI), set `DSH_HUB_SKIP_SELF_TEST=1`; the package
then has no self-test evidence.

For UI smoke tests in a development checkout:

```bash
DSH_HUB_ROUTE=plugins \
DSH_HUB_CAPTURE="$(pwd)/.data/shot.png" \
npm start
```

The capture is written after 4 seconds. `DSH_HUB_CAPTURE_JS` can click a
control before the capture; `DSH_HUB_CAPTURE_DELAY` changes the wait. In the
current sandboxed host, `npm start` automatically adds `--no-sandbox` to the
development child process; normal terminals keep Chromium's sandbox.

## Versioning

- `package.json.version` is the single source of truth.
- Update `CHANGELOG.md` and `src/shared/constants.js` (`APP_VERSION`) when
  releasing. The build script overrides the runtime package version, but the UI
  version comes from `APP_VERSION`.
- Tag releases as `vX.Y.Z`.

## Code signing

This project does not sign builds. Windows SmartScreen may warn on an unsigned
EXE. If you distribute publicly, sign `DSH-Hub.exe` and the installer/folder
with an Authenticode certificate, and publish SHA-256 checksums.
